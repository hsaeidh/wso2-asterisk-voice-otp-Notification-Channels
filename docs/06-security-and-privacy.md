# Security and Privacy Requirements

## 1. Security principles

- WSO2 remains the security authority for OTP and challenge lifecycle.
- Least privilege for ARI and administrative APIs.
- Secrets are write-only and stored using WSO2's supported secret mechanism.
- No OTP in persistent storage or diagnostic output.
- Organization isolation is enforced server-side.
- All external communication is authenticated and encrypted.
- Failure handling must not disclose account existence or challenge details.

## 2. OTP handling

The OTP is highly sensitive authentication data. It must:
- Be generated by WSO2's existing OTP/challenge mechanism.
- Exist in memory only for the minimum duration required for delivery.
- Be passed only across a narrowly scoped internal service boundary.
- Never appear in logs, traces, exception messages, metrics, audit payloads, database rows, ARI app arguments, channel names or UserEvent fields.
- Be cleared from mutable buffers/variables where technically possible after use.
- Never be returned by provider management APIs or delivery status APIs.

The ARI-to-dialplan handoff is a critical design review item. Asterisk dialplan variables and verbose logging can expose values. The implementation must inspect actual Asterisk logging behavior and choose a safe handoff; a comment saying "do not log" is not enough.

## 3. ARI credential protection

- Dedicated ARI account; no administrative privileges.
- Restrict allowed ARI applications and operations to those needed for OTP calls.
- TLS with certificate validation.
- No disabling hostname or certificate validation in production.
- Rotate credentials without logging values.
- Apply network ACLs between WSO2 and Asterisk.
- Never include credentials in URLs, query strings or exception messages.

## 4. SSRF and endpoint validation

Because administrators configure an ARI URL, validate it as an outbound network destination:
- HTTPS required outside explicitly isolated development.
- Reject URL user-info and unexpected schemes.
- Block cloud metadata, loopback, link-local and private ranges unless explicitly allowlisted by deployment policy.
- Restrict redirects or disable them.
- Apply connect/read deadlines and response-size limits.
- Avoid following arbitrary redirects to a different host.
- Consider DNS rebinding and resolve/validate destination addresses at connection time.

## 5. Organization authorization

- Derive organization from authenticated WSO2 context.
- Authorize each provider CRUD/test operation.
- Enforce organization-scoped uniqueness and secret references.
- Prevent cross-organization provider discovery through errors and timing.
- Test parent/child organization behavior in the actual IS 7.3.0 configuration.

## 6. Logs, audit and observability

Allowed:
- Opaque delivery ID
- Provider identifier (non-secret)
- Organization identifier where policy permits
- State transitions and timestamps
- Sanitized error category
- ARI call identifier if it does not contain sensitive data

Forbidden:
- OTP
- ARI password/token
- Full phone number unless strictly required and access-controlled
- Raw challenge payload
- HTTP Authorization headers
- Unredacted ARI request/response bodies

Audit administrative provider changes without storing submitted secret values. Review WSO2, Java HTTP client and Asterisk debug/verbose logs.

## 7. Toll fraud and call abuse

- Restrict destination country/prefix/rate according to organization policy.
- Limit call duration and ringing duration.
- Enforce per-destination and per-organization quotas.
- Require elevated permission for test calls.
- Prevent user-controlled dialplan contexts, endpoints or arbitrary application names.
- Never allow a user to supply an arbitrary ARI command.

## 8. Privacy and retention

Define retention for delivery metadata and audit records before production. Mask phone numbers in UI and logs. Keep only the metadata required for troubleshooting and replay protection. Follow the organization's data-protection and telecom retention requirements.

## 9. Security release gate

No production release until OTP-leakage tests, secret-redaction tests, SSRF tests, organization-isolation tests, ARI least-privilege tests and toll-fraud/rate-limit tests pass.
